# Personal Money Manager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deployable mobile-first React and Express money logger with secure single-user authentication, persistent Neon PostgreSQL records, unified history, dashboard aggregates, and chart-ready analytics.

**Architecture:** Vite builds the React client and proxies `/api` to Express in development; Express serves the built client and REST API in production. Drizzle with Neon's serverless PostgreSQL driver is the only database access path, while shared Zod schemas define client/server request contracts.

**Tech Stack:** TypeScript, React, Vite, Express 5, Zod, Drizzle ORM/Kit, Neon serverless PostgreSQL, Luxon, decimal.js, Vitest, Testing Library, Supertest, Playwright.

## Global Constraints

- The app is private and single-user; do not add users, roles, accounts, categories, balances, or record editing.
- Transactions, lent money, and borrowed money remain separate record types.
- IDs and `created_at` values are generated by PostgreSQL; the client never submits timestamps.
- Amounts use `NUMERIC(20,2)`, cross the API as decimal strings, and are never authoritatively calculated with JavaScript floating point.
- Every financial endpoint requires an authenticated HTTP-only cookie session.
- `DATABASE_URL`, `APP_PASSWORD`, and `SESSION_SECRET` remain server-only.
- The runtime must not fall back to mock financial data when Neon is missing.
- Local-date boundaries use the IANA timezone configured by `APP_TIMEZONE`.
